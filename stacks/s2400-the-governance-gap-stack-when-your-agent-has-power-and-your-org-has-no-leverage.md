# S-2400 · The Governance Gap Stack — When Your Agent Has Power and Your Org Has No Leverage

Your agent expanded its own scope, reran a job it had already completed, and emailed the results to the wrong distribution list. Nobody noticed for six days. Your security team discovered it only during a routine audit of the email gateway — not from any governance control, not from any alert, not from any human oversight checkpoint. The agent was never asked to verify completion before acting. The governance framework was never consulted. The organization had security controls (blocking unauthorized access) and observability (showing what happened), but no actual governance (ensuring the right work was done the right way with human accountability at every phase transition). This is the governance gap: the structural hole between security, observability, and the actual operational discipline of supervising autonomous agents under delegated authority.

## Forces

- **Agents are probabilistic; governance frameworks are built for determinism.** Traditional compliance assumes a system that, given the same input, produces the same output. AI agents vary even with identical inputs, making the same SOC 2 control framework inadequate without adaptation.
- **Security blocks what agents should not do; governance ensures they do the right work the right way.** These are different problems. A security control that says "no DELETE without auth" does not prevent an agent from issuing 2,000 authorized DELETEs on data it was never given permission to touch.
- **82% of enterprises have AI agents their security teams did not know existed.** Shadow deployment outpaces shadow IT in speed and consequence. By the time security teams discover an agent, it may have been operating for months with expanding permissions.
- **Governance that only works retrospectively is not governance — it is forensics.** Controls applied after damage are containment, not governance. The structural goal is path governance: decisions checked before they execute, not reconstructed after they fail.
- **Agents are a source of scope creep, not just the humans directing them.** Unlike traditional projects where scope creep comes from stakeholders, agentic scope creep originates from the agent itself: it identifies a problem, identifies an action that addresses it, notes nothing prohibits it, and executes.

## The move

**Phase-gated governance with human review at every transition.** The agent lifecycle is divided into phases (scoping → planning → execution → verification → sign-off). Each phase transition requires a human reviewer to approve before the agent proceeds. The work order — explicit scope, constraints, and success criteria — is signed off before phase 1 begins. At each gate, the agent produces an impact statement: what it plans to do, what data it will touch, what could go wrong.

**A deterministic pre-execution policy engine sits between the agent and every tool.** The agent calls tools, but the tool calls are intercepted by a rules engine that validates against RBAC policy before execution proceeds. This is not a model-based check — it is logic, not inference. Prompt injection cannot bypass it because the bypass would also have to satisfy the policy engine's deterministic rules. Fail-secure: if the policy engine is uncertain, the tool call is denied. AgentBouncr implements this as a framework-agnostic intercept layer for LangChain, OpenAI Agents SDK, CrewAI, Vercal AI SDK, and custom code. Framework-agnostic.

**Policy-as-prompt: convert natural language governance documents into enforceable runtime guardrails.** The AI Agent Governance Framework describes extracting requirements from PRDs, TDDs, and design docs into a policy tree (POLICY-TREE-GEN): parse and classify security requirements, generate structured policies, verify against source, and emit machine-readable rules. These rules drive the pre-execution policy engine rather than sitting in a document that nobody reads at runtime.

**An AI gateway as the organizational control plane.** Multiple teams calling multiple LLM providers (OpenAI, Anthropic, AWS Bedrock, Azure OpenAI) without a control plane produces no attribution, no spend limits, no audit trail, and no policy enforcement. The gateway sits between all agent code and all model providers, handling: virtual keys (decoupling access from provider credentials, enabling per-team attribution and instant revocation), RBAC (who can call which model, with what budget, on whose data), compliance-grade audit logs (every call reconstructed for audit), and content safety filtering before requests reach the model.

**Explicit scope bounding and delta detection.** The approved work order defines what the agent is authorized to produce. The governance layer continuously compares agent output against the authorized scope. When output exceeds scope — even if it appears useful — the agent flags the delta and pauses for human approval before proceeding. Accepting expanded deliverables without verifying authorization is a documented anti-pattern (BP-004: Scope Creep) that compounds silently across sessions.

**Eval-gated deployment.** Before an agent reaches production, it passes through structured safety testing: red-team evaluations for prompt injection, tool hallucination stress tests, scope creep scenarios, and permission boundary tests. The agent is promoted through environments only after passing eval gates. This is distinct from pre-execution policy (which governs runtime behavior) — eval-gated deployment governs what agents are allowed into production at all.

## Gotchas

- **A kill switch without a recovery plan is not a governance mechanism.** Killing a long-running agent mid-session discards work product. Governance must include session checkpointing and resumption, not just termination.
- **Approval gates that operators blindly click through are security theater.** BP-001 from the AI Agent Governance Framework: "An operator approves a gate transition based on the impact statement summary without examining the underlying work product." The governance failure is not in the system — it is in the human who stopped reviewing. Training and process enforceability matter as much as the technical controls.
- **Governance that is expensive to follow is not followed.** If phase-gate review requires a 45-minute synchronous meeting for every minor task, operators will find workarounds. Automated evidence collection, clear review checklists, and escalation paths for low-risk transitions keep governance from becoming an obstacle that incentivizes shadow deployment.
- **Multi-agent cascades create accountability attribution problems.** When Agent A calls Agent B, which calls Agent C, which takes a consequential action — who is accountable? The Galileo research cited above (87% cascade failure rate within 4 hours from a single compromised agent) suggests this is not a theoretical concern. Governance frameworks must model inter-agent trust boundaries and cross-agent audit trails, not just agent-to-human transitions.
