# S-1837 · The Agent Black-Box Stack — When Your Agent Scores Perfectly But Breaks in Production

Your agent scores 94% on your eval suite. You ship it. Two days later a production trace surfaces a loop through a broken vector index that happens to succeed on your test queries, a tool call that took 47 steps for a task a human does in 3, and a silent context overflow that made the agent hallucinate an order number it never actually retrieved. The eval suite was the problem — it tested the answer, not the trajectory. This is the agent evaluation gap: the gap between measuring what an agent outputs and measuring whether it works.

## Forces

- **Trajectory blind spots are invisible to output-only evals.** An agent can call the wrong tool for the right reason, loop through retrieval six times instead of once, and still land on a correct answer. Standard eval suites and LLM-as-judge on final answers miss all of this. — *[LangChain Agent Evals, 2025](https://www.langchain.com/resources/agent-evals)*
- **Agents are non-deterministic in a way that breaks traditional software testing.** Unit tests assume deterministic output — function A returns value B for input C. Agents reason, choose tools, and navigate multi-step workflows in ways that vary each time. "Standard unit tests are pretty much useless for agents." — *[Cleanlab AI Agents in Production 2025 survey](https://cleanlab.ai/ai-agents-in-production-2025), 95 enterprise respondents*
- **Production exposes the gaps that curated datasets miss.** Even within the 5% of enterprises that have agents live in production, most teams are still early-stage: 70% rebuild their AI agent stack every 3 months or faster. The eval tooling to *see* what agents do has outpaced the tooling to *judge* whether they're doing it well. — *[Cleanlab/ MIT State of AI survey, 2025](https://cleanlab.ai/ai-agents-in-production-2025)*
- **The journey matters as much as the destination in agentic tasks.** Unlike model benchmarks, agent evaluation must assess the trajectory: the end-to-end sequence of reasoning, tool calls, and observations in a non-deterministic environment. — *[NVIDIA Technical Blog, Mastering Agentic Techniques: AI Agent Evaluation, May 2026](https://developer.nvidia.com/blog/mastering-agentic-techniques-ai-agent-evaluation)*

## The Move

Move up the eval depth hierarchy — from testing outputs to testing trajectories to testing individual decisions:

- **Test the trajectory, not just the output.** Capture and evaluate the full sequence of tool calls, reasoning steps, and intermediate observations. A correct answer on a broken execution path is a regression waiting to happen. Use SDK lifecycle hooks (`PreToolUse`, `PostToolUse`) to instrument every agent action. — *[TribeAI/claude-evals](https://github.com/TribeAI/claude-evals), Anthropic partner launch pattern, 2026*
- **Build a golden dataset from production failures.** The most representative test cases come from real production runs, especially the ones that went wrong. Seed datasets from caught regressions, support escalations, and observed edge cases. Treat eval datasets like code: versioned, owned, PR-reviewed. — *[AI Workflow Lab, "Test AI Agents in Production 2026", Mar 2026](https://aiworkflowlab.dev/article/test-ai-agents-production-trajectory-evaluation-tool-validation-python); [Maxim AI, "Building a Golden Dataset for AI Evaluation", 2026](https://www.getmaxim.ai/articles/building-a-golden-dataset-for-ai-evaluation-a-step-by-step-guide)*
- **Test the failure modes explicitly, not the happy paths.** A minimum coverage checklist: happy paths, ambiguous requests (missing IDs, unclear goals), multi-turn churn, tool failure modes (timeouts, partial results, stale data), policy-bound refusals, adversarial prompts (prompt injection), and conflicting-source retrieval. Prompt injection testing should be part of the core suite, not an afterthought. — *[StackAI eval checklist](https://www.stackai.com/insights/how-to-evaluate-and-test-ai-agents-before-deploying-to-production); [HN Ask thread #47325105](https://news.ycombinator.com/item?id=47325105)*
- **Use LLM-as-judge at the trajectory level, not just answer level.** Evolving to "Agent-as-a-Judge" — using AI agents to evaluate the full reasoning and action trajectory, not just the final answer. Particularly effective for open-ended, multi-step tasks where the process matters. — *[arxiv:2508.02994, "When AIs Judge AIs: The Rise of Agent-as-a-Judge", 2025](https://arxiv.org/html/2508.02994v1)*
- **Instrument three levels: black-box (final output), glass-box (trajectory), white-box (single-step decision).** Each layer answers a different diagnostic question. Black-box tells you *what* failed. Trajectory tells you *where*. White-box tells you *why*. — *[AI Workflow Lab, 2026](https://aiworkflowlab.dev/article/test-ai-agents-production-trajectory-evaluation-tool-validation-python)*
- **Ground truth on cost and latency.** Agent evaluation must include cost-per-task and latency-per-step metrics, not just accuracy. A trajectory that works but costs 10× more than a well-prompted single-agent is a production regression. — *[NVIDIA, 2026](https://developer.nvidia.com/blog/mastering-agentic-techniques-ai-agent-evaluation)*

## Evidence

- **HN Ask thread (harperlabs):** 7 core failure modes identified from production incidents: hallucination under unexpected inputs, edge case collapse (nulls, Unicode names like O'Brien/José/北京), prompt injection, context limit surprises, cascade failures, tool call loops, and silent hallucination. Context: Gartner predicted >40% of AI agent projects will fail by 2027; a Jan 2026 prompt injection in a customer support agent processed a $47,000 fraudulent refund. — [HN #47325105](https://news.ycombinator.com/item?id=47325105)
- **Cleanlab survey (n=95 production teams):** Only 5% of 1,837 surveyed enterprises have AI agents live in production. Of those: 89% have observability tooling but only 52% run offline evals and 37% run online evals. 70% rebuild their stack every 3 months or faster. — *[Cleanlab/ MIT State of AI in Business 2025](https://cleanlab.ai/ai-agents-in-production-2025)*
- **LangChain Agent Evals:** Production traces seed offline test datasets — a caught failure in production becomes a regression test case. Framework covers run-level (end-to-end), trace-level (per tool-call sequence), and thread-level (multi-turn conversation) evaluation. 89% orgs have observability; the gap is judgment tooling. — *[LangChain Agent Evals](https://www.langchain.com/resources/agent-evals)*

## Gotchas

- **Golden datasets drift.** Production behavior changes as models, prompts, and tools evolve. A golden dataset that isn't refreshed from production failures becomes a false signal — passing it means nothing. Rebuild datasets quarterly from production traces.
- **LLM-as-judge has a self-preference bias.** Models tend to prefer their own reasoning style. Use a separate, dissimilar judge model or combine automated metrics (tool call accuracy, step count, cost) with LLM-as-judge to avoid false confidence.
- **Coverage ≠ quality.** A 200-case eval suite covering every edge case can still miss the single interaction pattern your users actually hit. Weight test cases by production frequency, not uniformity.
- **Trajectory logging is expensive.** Capturing every tool call and intermediate step at scale generates large trace volumes. Plan for storage and sampling — you can't keep everything, so sample strategically from production traffic and log everything from regressions.
