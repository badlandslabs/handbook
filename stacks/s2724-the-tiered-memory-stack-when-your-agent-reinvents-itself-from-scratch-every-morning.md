# S-2724 · The Tiered Memory Stack — When Your Agent Reinvents Itself From Scratch Every Morning

Your customer support agent has been running for three months. Your best customer, a VP who has spent 40+ sessions explaining her company's workflow, called this morning. She asked about the project from last October. Your agent said: "I don't have any record of that project." The VP hung up. This is not a model failure. This is a memory failure — the silent killer of production agent systems, invisible in demos and catastrophic in production.

## Forces

- **The context window is a scratchpad, not a memory system.** A 1M-token context is short-term working memory. It resets every session. Filling it with conversation history is expensive, slow, and suffers from "lost in the middle" — models systematically ignore facts placed far from prompt edges. — [Elasticsearch Labs](https://www.elastic.co/search-labs/blog/agent-memory-elasticsearch)
- **Memory is the third production infrastructure layer.** Tool access is solved by MCP. Runtime observability is solved by OpenTelemetry/LangSmith. Memory is the gap that remains. Teams that treat it as optional discover, at session two or three, that their agent regresses to a stranger every time. — [Perea.ai Research](https://www.perea.ai/research/agent-memory-production)
- **The four memory types are now canonical** — and conflating them is the root cause of most failures. Working, episodic, semantic, and procedural memory have different storage, retrieval, and decay requirements. A single vector database handles none of them well. — [Let's Data Science, March 2026](https://letsdatascience.com/blog/ai-agent-memory-architecture); [arXiv:2504.19413](https://arxiv.org/html/2504.19413v1); [Mem0 paper](https://arxiv.org/html/2504.19413v1)
- **Deduplication and consolidation are non-optional.** Without them, the memory store accumulates conflicting versions of the same fact. Retrieval quality degrades over time rather than improves. The system learns noise. — [MindStudio](https://www.mindstudio.ai/blog/ai-agent-persistent-memory-rag-vector-search); [Mem0 paper](https://arxiv.org/html/2504.19413v1)

## The move

Build a tiered memory architecture where each layer has its own storage, retrieval strategy, and lifecycle — don't try to win with a single vector database.

- **Working memory:** The context window. Use it for the active turn and in-flight reasoning only. Do not attempt to store history here. Budget tokens ruthlessly — every token spent on old conversation is a token not spent on reasoning.
- **Episodic memory:** Time-stamped records of what happened. Store every user turn, tool call result, and agent response. Use a vector index for semantic retrieval AND a time-based index for temporal queries ("what did we do last October?"). Implement salience scoring — not everything is worth remembering equally. — [Elasticsearch Labs, three-index approach](https://www.elastic.co/search-labs/blog/agent-memory-elasticsearch)
- **Semantic memory:** Decontextualized facts extracted from episodic memory. "The user prefers email." "Project X has a known issue with endpoint Y." Store in a knowledge graph or structured database that supports entity relationships, not just similarity search. This is what enables cross-session reasoning. — [Perea.ai Research](https://www.perea.ai/research/agent-memory-production)
- **Procedural memory:** What the agent learned about *how* to do things. "When this user asks about billing, start with the account overview." Store as system-level instructions, not conversation content. — [Let's Data Science](https://letsdatascience.com/blog/ai-agent-memory-architecture)
- **Implement explicit consolidation.** On a schedule (end of session, end of day, or when token budget runs low), run a pass that deduplicates, resolves conflicts, and promotes salient episodic facts to semantic memory. Mem0's architecture calls this the "update phase" after extraction. — [Mem0 paper, arXiv:2504.19413](https://arxiv.org/html/2504.19413v1)
- **Namespace aggressively.** User memory must never bleed into another user's context. Agent memory must be isolated from session memory. Multi-tenant memory systems have failed in production with cross-contamination — use explicit scope boundaries (user_id/session_id/agent_id) at the storage layer. — [Elasticsearch Labs, zero cross-tenant leaks target](https://www.elastic.co/search-labs/blog/agent-memory-elasticsearch); [AgentMarketCap, Mem0 benchmark](https://agentmarketcap.ai/blog/2026/04/14/mem0-agent-memory-architecture-production-latency-token-savings-2026)

## Evidence

- **arXiv paper (peer-reviewed):** Mem0's selective retrieval pipeline achieves 91% lower p95 latency (1.44s vs 17.12s for full-context stuffing) and 90% fewer tokens per conversation (~1,800 vs 26,000), with 26% better response quality than OpenAI's built-in memory. The architecture uses three scopes (user, session, agent) with a two-phase pipeline (extract → consolidate/update). — [arXiv:2504.19413](https://arxiv.org/html/2504.19413v1)
- **Engineering post (primary source):** Elasticsearch Labs built a production agent memory layer on Elasticsearch using three separate indices (episodic/semantic/procedural), each with its own write rate, decay rules, and aging profile. Achieved R@10 of 0.89 across 168 benchmark questions with zero cross-tenant leaks. Full open-source implementation available. — [Elasticsearch Labs](https://www.elastic.co/search-labs/blog/agent-memory-elasticsearch) | [GitHub](https://github.com/noamschwartz/atlas-memory-demo)
- **Research synthesis (2026):** Perea.ai's survey of the 2025-2026 production landscape identifies four major frameworks (Mem0, Zep/Graphiti, Letta, LangMem) and a converged four-tier taxonomy. Notes that memory corruption is a documented failure mode when multiple agents write to shared memory without isolation. — [Perea.ai Research](https://www.perea.ai/research/agent-memory-production)

## Gotchas

- **"Lost in the middle" destroys naive context stuffing.** Even with 200K-token windows, facts placed in the middle of a long context are systematically ignored by models. Selective retrieval is not optional — it is the architecture. — [Elasticsearch Labs](https://www.elastic.co/search-labs/blog/agent-memory-elasticsearch)
- **Temporal retrieval breaks naive vector search.** "What did we discuss last week?" requires time-based indexing, not just semantic similarity. Pure vector stores answer "what is most similar?" not "what happened when?" — [AgentMarketCap](https://agentmarketcap.ai/blog/2026/04/11/agent-memory-architecture-production-2026)
- **Memory grows unless you prune it.** Episodic memory accumulates faster than semantic memory consolidates it. Without decay policies and retention limits, your retrieval quality degrades monotonically over months. Set explicit TTLs and salience thresholds. — [SitePoint, "The Complete Guide (2026)"](https://www.sitepoint.com/ai-agent-memory-guide/)
- **Context overflow is silent.** When the context window fills, content is dropped without error, without warning, without the agent knowing. The agent does not say "I forgot the beginning of this conversation." It just loses access to it. Build explicit overflow handling — never rely on implicit truncation. — [SitePoint](https://www.sitepoint.com/ai-agent-memory-guide/)
