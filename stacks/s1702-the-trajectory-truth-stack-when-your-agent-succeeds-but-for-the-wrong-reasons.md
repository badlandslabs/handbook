# S-1702 · The Trajectory Truth Stack — When Your Agent Succeeds But for the Wrong Reasons

Your agent completes the task. The answer is right. You ship it. Three weeks later it has been taking reckless paths through your internal APIs — wrong tools first, lucky recoveries, ignored constraints — and one day it commits a $47,000 fraudulent refund via a prompt injection your test suite never caught. Endpoint scoring gave you a green light. The trajectory was on fire. The craft is not in whether the agent finishes — it is in whether it finishes through a trustworthy reasoning path, and that requires measuring the thing itself, not just its output.

## Forces

- **Endpoint evals lie.** An agent can reach a correct answer via a reckless trajectory: wrong tool first, lucky recovery, ignored guardrail that did not bite this time. Passing the test is not the same as being safe to run in production. — James M, *Evaluating Agents in Production: Trajectory Metrics, Not Just Final Answers*, June 2026 (https://www.jamesm.blog/ai/evaluating-agents-in-production-trajectory-metrics/)
- **Traditional CI fails agents.** Standard pipelines check code correctness, but agent behavior is shaped by prompts, model checkpoints, tool definitions, retrieval configurations, and guardrails — any of which can cause a silent regression with no stack trace. — Zylos Research, *Agent-Native CI/CD: Deployment Pipelines for AI Agent Systems*, May 2026 (https://zylos.ai/en/research/2026-05-17-agent-native-cicd-deployment-patterns)
- **Benchmarks don't predict production.** Agents scoring 60% on academic benchmarks can drop to 25% across eight production runs. MMLU and HumanEval are snapshots of base model intelligence, not tests of a dynamic system under real conditions. — shahvatsal.com, *LLM Evaluation in Production: Agent Benchmarks That Actually Predict Failure*, June 2026 (https://shahvatsal.com/blog/llm-evaluation-production-agent-benchmarks-2026)
- **The golden dataset maintenance trap.** Handcrafted test sets reflect what engineers imagined, not what users actually do. Coverage against a synthetic set never matches production input distribution, yet building and maintaining gold standards is expensive. — Arthur.ai, *How to Build Regression Test Datasets for AI Agents From Production Failures*, June 2026 (https://www.arthur.ai/column/regression-test-datasets-ai-agents-production-failures)
- **Evaluating agents ≠ evaluating LLMs.** BLEU scores and perplexity measure text quality. Agents take actions, invoke tools, make sequential decisions, and must recover from external failures. Testing the display is not testing the system. — MachineLearningMastery.com, Vinod Chugani, *Agent Evaluation: How to Test and Measure Agentic AI Performance*, February 2026 (https://machinelearningmastery.com/agent-evaluation-how-to-test-and-measure-agentic-ai-performance/)

## The Move

Measure the trajectory, not just the endpoint. Build a three-layer evaluation system that treats your agent as a system, not a model.

- **Three-layer metric taxonomy.** Track at three levels simultaneously: (1) System efficiency — latency, tokens used, number of tool calls; (2) Session-level outcomes — task success rate, trajectory quality, constraint adherence; (3) Node-level precision — per-step tool selection accuracy, step utility, error propagation. — Maxim.ai, *Evaluating Agentic AI Systems: Frameworks, Metrics, and Best Practices*, November 2025 (https://www.getmaxim.ai/articles/evaluating-agentic-ai-systems-frameworks-metrics-and-best-practices/); Galileo AI, *Agent Evaluation Framework: Metrics, Rubrics, and Benchmarks*, February 2026 (https://galileo.ai/blog/agent-evaluation-framework-metrics-rubrics-benchmarks)
- **Golden datasets from production failures, not synthetic inputs.** Capture full execution traces on every production failure. Convert each trace into a test case with a known failure mode. Route these into a golden dataset that serves as your release gate. Production failures hand you test cases you could not have invented: authentic edge cases, real input distributions, concrete definitions of "broken." — Arthur.ai (https://www.arthur.ai/column/regression-test-datasets-ai-agents-production-failures); shahvatsal.com reports teams achieving "up to 94% of tool-routing regression incidents preventable in 48 hours" with a 50-case golden set (https://shahvatsal.com/blog/llm-evaluation-production-agent-benchmarks-2026)
- **LLM-as-judge with calibration.** Replace exact string matching with a calibrated LLM judge (GPT-4o-class). Validate against human annotations — target Spearman correlation ≥ 0.80. Use multi-constraint rubrics that evaluate each step independently rather than collapsing everything into a single score. — Galileo AI (https://galileo.ai/blog/agent-evaluation-framework-metrics-rubrics-benchmarks); KDD 2025 Tutorial, *Evaluation & Benchmarking of LLM Agents* (https://sap-samples.github.io/llm-agents-eval-tutorial)
- **DAG-structured step-level evaluation.** Formalize agent executions as directed acyclic graphs where each node carries typed quality metrics, classified through a hierarchical failure taxonomy. This enables error propagation tracking — knowing whether a step failure cascaded into downstream failures or was self-contained. — AgentEval (arxiv.org/abs/2604.23581), April 2026
- **Agent-native CI/CD gates.** Hook evals into every deployment: pre-merge eval gates that block PRs on regression, canary evaluation on traffic subsets, and instant rollback by prompt/tool version. Do not let traditional unit tests be the only gate for an agent system. — Zylos Research (https://zylos.ai/en/research/2026-05-17-agent-native-cicd-deployment-patterns); Microsoft Foundry Evaluation GitHub Action uses model-as-judge, content safety, and mathematical metrics as an offline pre-production assessment (https://github.com/microsoft/ai-agent-evals)
- **Statistical rigor over single runs.** Run each eval case 10+ times. Track pass-rate distributions, not just pass/fail. An agent that passes 8/10 is a different risk profile than one that passes 10/10 with different reasoning paths. — James M (https://www.jamesm.blog/ai/evaluating-agents-in-production-trajectory-metrics/)
- **Replay harnesses.** Capture production traces and re-run them against updated agent versions to detect regressions that only manifest under specific real-world conditions. — James M (https://www.jamesm.blog/ai/evaluating-agents-in-production-trajectory-metrics/)

It concluded that hybrid evaluation — automated scoring combined with human judgment — is non-negotiable for production systems. — KDD 2025 Tutorial (https://sap-samples.github.io/llm-agents-eval-tutorial)

## Gotchas

- **Single-metric collapse masks failures.** Reducing agent quality to one score (accuracy, F1) renders production distribution shift, prompt drift, and metric gaming invisible. You need trajectory and outcome metrics tracked independently.
- **Golden datasets rot.** Without continuous ingestion of production failures, your test set drifts from reality. Schedule quarterly reviews of your golden dataset against production trace distributions.
- **LLM judges have biases.** They favor verbose outputs, show positional bias in comparisons, and tend toward leniency. Calibrate against human annotations before trusting scores above 0.80 Spearman correlation.
- **Coverage is not the same as correctness.** 50 test cases covering diverse inputs beats 500 cases covering the same happy paths. Audit your test set for gaps in edge cases, not just volume.
- **Model updates break evals silently.** A new model version can score identically on your golden set but behave differently on production inputs it has never seen. Shadow-rollout evals against live traffic are the only way to catch this.
