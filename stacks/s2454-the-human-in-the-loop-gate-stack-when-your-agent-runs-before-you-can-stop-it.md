# S-2454 · The Human-in-the-Loop Gate Stack — When Your Agent Runs Before You Can Stop It

Your agent deletes 200 customer records at 2am. It misread context and acted on stale state. No one reviewed the action before execution — because the architecture had no checkpoint, no gate, and no way to interrupt. The merge request analogy works perfectly here: the pipeline ran without a reviewer, and by the time anyone noticed, the blast radius was already measured.

## Forces

- **Autonomy and safety are in tension.** More autonomous agents are more useful — but more capable of irreversible damage. Fully autonomous agents are the goal, but you earn that trust through measured reliability, not deployment faith.
- **"Pause and wait" is architecturally non-trivial.** Most frameworks are built for synchronous execution. Making a workflow suspend mid-run, persist state durably, and resume from the exact same point requires explicit infrastructure that doesn't exist by default.
- **Not every action needs a gate.** Reads, reversible operations, and user-requested actions don't need human review. Gating everything slows agents to a crawl and trains teams to click-approve reflexively.
- **Context loss on resume is a silent killer.** If state isn't checkpointed durably before interruption, a server restart kills the pending action and the agent has no idea where it left off.

## The move

**Use interrupt-and-resume to gate irreversible actions with human approval, checkpointing state durably so agents can be safely paused, inspected, and resumed.**

- **Gate what bites.** Approval gates are mandatory before: sending emails/notifications, modifying/deleting production records, financial transactions, publishing public content, high-cost API calls beyond a threshold. Gates are unnecessary for read-only operations, reversible actions, or explicitly user-requested tasks.
- **Pause with `interrupt()` (LangGraph) or equivalent.** Call `interrupt(value)` to suspend the graph mid-execution, surfacing state to the caller. The agent freezes; the full state — tool results, LLM reasoning, action intent — is serialized to durable storage (PostgresSaver in production, MemorySaver for dev).
- **Resume with explicit approval.** Use `Command(resume=...)` to feed the human's decision back into the graph. If approved, execution continues from the exact checkpoint. If rejected, the branch aborts cleanly.
- **Start simpler before you reach for orchestration.** Anthropic's engineering guidance (December 2024) is blunt: "Consistently, the most successful implementations use simple, composable patterns rather than complex frameworks." A single LLM call with 3–5 well-scoped tools beats a multi-node graph with approval gates added as an afterthought. Reach for HITL when you have branching logic, approval-required substeps, or crash-resume requirements — not before.
- **Pair checkpointing with the right checkpointer for the job.** In-process MemorySaver works for development. Production needs `AsyncPostgresSaver` (or LangGraph Platform's managed Postgres checkpointer) so state survives process restarts. A server crash mid-gate without durable checkpointing means the pending action is lost with no recovery path.
- **Scope tool permissions, not just human approval.** Claude Managed Agents (Anthropic, April 2026) separates the execution harness (stateless step executor), session (append-only state log), and sandbox (isolated execution environment). Credentials and permissions are scoped per-action, not per-agent — so even if the agent decides to act, it may lack the credentials to execute without an additional human step.

## Gotchas

- **Gating too many actions trains approval fatigue.** If every tool call requires a human click, teams build muscle memory to approve without reading. Scope gates to genuinely irreversible or externally visible actions only — reads and reversible steps should flow freely.
- **In-memory checkpointers die on restart.** MemorySaver and AsyncSqliteSaver are fine for development. In production, a deploy that restarts the process mid-gate loses all pending interrupted runs. PostgresSaver or LangGraph Platform's managed checkpointer is the minimum for production.
- **Thread ID collisions corrupt state.** Every interrupted run needs a unique `thread_id`. Two concurrent tasks with the same thread ID overwrite each other's checkpoint state — silently, with no error. Bind thread IDs to a session or request ID from the start.
- **interrupt() in a conditional branch can deadlock.** If the LLM routes to the interrupt node but the caller never reads the pending action, the run hangs indefinitely with no timeout. Implement a watchdog that abandons stale interrupted runs after a configurable max-wait period.
