# S2198 · The Agent Eval Gap Stack — You Can't Tune What You Can't Measure

You have agents running in production. You think they're working. You ship a change. Nothing breaks in your test suite. Three weeks later you discover the agent has been failing silently on 23% of requests since the day after deployment.

## Forces

- **Traditional benchmarks are blind to trajectories.** MMLU, HumanEval, and BLEU/ROUGE score the output, not the path. An agent can complete a task correctly but waste 47 tool calls doing it — or fail silently on edge cases with a plausible-sounding answer.
- **Agents are composite systems, not models.** Evaluating them like a model misses every failure mode that lives in the glue: routing, tool calling, memory retrieval, recovery from dead ends.
- **Perfect evaluation is prohibitively expensive.** Human review of every agent run is the gold standard but doesn't scale. Automated eval is cheap but misses tone, trust, and contextual appropriateness.
- **Benchmark scores don't predict production performance.** The gap between benchmark-land and live systems is so pronounced that even the best agent configurations score only 64/100 on production-grounded tasks (AlphaEval, 94 real tasks from 7 companies).
- **63% of teams plan to improve observability and evaluation** in the next year — it's the industry's most acute unsolved problem (Cleanlab, 2025).

## The Move

Build a layered evaluation stack that measures trajectory, not just terminal output. The key moves:

- **Trace everything first.** Capture every LLM call, tool invocation, and reasoning step as a structured trace. Treat traces as first-class artifacts — LangSmith, Langfuse, OpenTelemetry, and OpenAI's Agents SDK all produce them. Without traces, you have no data to eval against.
- **Score three things separately: task success, trajectory quality, and operational health.** Amazon's three-layer evaluation framework distinguishes these: did the agent complete the right task (task success), did it do so efficiently without wasted steps (trajectory quality), and is it within latency/cost bounds (operational). Scoring all three together collapses signal.
- **Use hybrid evaluation: automated + human.** Automated scoring (LLM-as-judge, trace analysis) gives repeatability and scale. Human judgment catches what automation misses: tone, trust, contextual appropriateness. Amazon calls hybrid "non-negotiable." The HN consensus from production teams is the same: "if you don't have evals, you really don't know if you're moving the needle at all."
- **Multi-agent debate beats single-model judges.** When using LLM-as-judge, single-model pointwise scoring shows bias toward its own writing style. Multi-agent debate frameworks (ChatEval, DEBATE) outperform single-agent approaches by combining diverse evaluator personas. CourtEval adds courtroom-style roles (Judge, Critic, Defender) for balanced deliberation. However: one HN practitioner who shipped production AI tools notes they've "never seen empirical evidence that LLM-as-critic works" — treat it as directional signal, not ground truth.
- **Evaluate on production data, not synthetic test sets.** AlphaEval (arXiv:2604.12162, April 2026) shows that scaffold choice matters as much as model choice — the same model varies 11–15 points depending on the scaffolding. Research benchmarks (SWE-bench, WebArena, OSWorld) use retrospectively curated tasks with deterministic solutions. Real production requirements are under-specified, evolving, and lack clean ground truth.

## Gotchas

- **Chasing a single-number score is a trap.** Teams optimize for benchmark accuracy and ship agents that are brittle in production. AlphaEval's 64/100 for the best configuration reflects the reality that production tasks are under-specified and don't have clean ground truth. A 70-80% pass rate on realistic production-grounded evals is meaningful; a 98% on MMLU is not.
- **LLM-as-judge needs calibration or it lies to you.** Without human-in-the-loop alignment, judges exhibit style bias (preferring outputs that resemble their own writing) and positional bias. The Confident AI guide recommends three human-in-the-loop workflows: metric alignment (fixing metrics that disagree with humans), failure review, and dataset curation. Start with 20–50 human-labeled examples to calibrate before trusting automated scores.
- **Evals go stale faster than your code.** Cleanlab found 70% of enterprises rebuild their agent stack quarterly. Your eval suite needs to evolve with your production surface — a stale eval suite is worse than no eval suite because it gives false confidence.
- **Trajectory cost is invisible without tracing.** An agent that completes a task correctly but makes 10x the necessary tool calls is a cost problem, not a quality problem — and you won't see it without trace-level observability. Amazon's three-layer framework makes operational metrics first-class evaluation targets.
- **Multi-agent debate frameworks add cost and complexity.** DEBATE and CourtEval outperform single-model judges but at higher compute cost and with more prompt engineering required. For most teams, starting with a well-calibrated single-model judge (with human alignment) is the right trade-off before investing in multi-agent evaluation infrastructure.
