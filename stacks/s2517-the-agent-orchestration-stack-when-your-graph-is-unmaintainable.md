# S-2517 · The Agent Orchestration Stack — When Your Graph Is Unmaintainable

You have two agents. You need three. Now you have a graph. You have a graph that nobody on the team can trace end-to-end, nobody knows what state it carries, and the moment something breaks you spend two hours reconstructing which node failed and why. This is the orchestration debt moment — the point where "just chain some LLM calls" stopped scaling and the graph started owning you. The move is picking the right coordination pattern for the actual dependency structure of your work.

## Forces

- **Chaining LLM calls collapses under its own weight.** By 2025, teams that started with sequential prompt chains hit deadlocks, state corruption, silent failures, and runaway costs. Agent coordination turned out to deserve the same engineering discipline as distributed systems — it just didn't look like it until things broke. — [Zylos Research, April 2026](https://zylos.ai/research/2026-04-14-agent-workflow-orchestration-patterns/)
- **Multi-agent orchestration is the default 2025-2026 answer — and also the default over-engineering mistake.** Most teams reach for it too early. A single agent with 3–5 well-scoped tools beats a three-node graph on cost, latency, and debuggability unless you genuinely have multiple tools, parallel exploration, or a handoff structure. — [Idea to MVP, June 2026](https://ideatomvp.ai/blog/langgraph-agent-orchestration-patterns-2026)
- **The framework matters less than the pattern.** "There's absolute 0 framework out there that's good enough for serious work" — experienced practitioners consistently build custom orchestration on top of a framework, not on the framework itself. — [HN Ask HN, ~4 months ago](https://news.ycombinator.com/item?id=47660705)
- **The stack churn is brutal.** 70% of regulated enterprises rebuild their AI agent stack every 3 months or faster. The orchestration layer is usually what breaks under production load, compliance requirements, or team turnover. — [Cleanlab, 2025](https://cleanlab.ai/ai-agents-in-production-2025)

## The move

**Pick the coordination pattern that matches the dependency structure, not the tool that matches the marketing.**

1. **Use the orchestrator-worker pattern as your default for complex tasks.** One central LLM dynamically breaks down the input, dispatches subtasks to specialized workers, collects results, and synthesizes the final output. The key distinction from parallel fan-out: subtasks are determined at runtime based on the input, not pre-defined. Anthropic's cookbook has the reference implementation; LangGraph implements it as the supervisor pattern. — [BuildingEffectiveAgents.com, 2026](https://buildingeffectiveagents.com/patterns/orchestrator-worker/)
2. **Use sequential pipeline when tasks have a fixed order.** A → B → C where B genuinely needs A's output. The moment B could start before A finishes, you're not in a pipeline anymore — you're in a DAG or event-driven model. Don't use pipeline when you mean fan-out.
3. **Use parallel fan-out + merge when subtasks are independent.** Dispatch N agents simultaneously, wait for all results, merge. This is where you get the most latency wins. The failure mode is a single slow worker holding up the whole run — set per-task timeouts and use the first K results if the task is embarrassingly parallel.
4. **Use a DAG (LangGraph, Dagster, Temporal) when you need deterministic replay.** The graph structure makes it possible to resume from any checkpoint, audit the execution path, and replay failures without re-running the whole pipeline. By 2025, this became the production-grade default over loose chaining. — [Zylos Research](https://zylos.ai/research/2026-04-14-agent-workflow-orchestration-patterns/)
5. **Use event-driven (Kafka + MCP/A2A) when you need loose coupling across team boundaries.** Microsoft's ISE team moved a retail customer from a modular monolith with a single router to microservices where agents communicate via typed message contracts — enabling reuse across teams and chat channels. The coordinator pattern (one agent orchestrates; others specialize) solved their cross-system reuse problem. — [Microsoft ISE Developer Blog, June 2026](https://devblogs.microsoft.com/ise/coordinator-patterns-multi-agent-systems)
6. **Build small, specialized, testable agents — not one general-purpose agent.** Kadoa's web scraper orchestration uses specialized agents for website loading, navigation, network analysis, and validation — each a medium-sized LLM prompt with a bounded function set. "Hard to control and test" is the signature of an agent that is too large. — [HN user hubraumhugo, February 2024](https://news.ycombinator.com/item?id=39373964)
7. **Combine patterns within a single workflow.** Production systems typically layer 2–3 patterns: a supervisor at the top decides whether to fan out or sequence, underneath you have a pipeline for the handoff chain, and individual nodes run agents with their own tool scopes. — [Thinking.inc, March 2026](https://thinking.inc/en/blue-ocean/agentic/agent-orchestration-patterns)

## Gotchas

- **The graph becomes unmaintainable before the graph solves your problem.** LangGraph has become the default answer for teams that already over-engineered — which means "use LangGraph" is often advice for fixing a problem that shouldn't exist. Start with a single agent + tools.
- **Crash recovery is an afterthought in most orchestration code.** If your graph can't resume from a mid-run checkpoint, you don't have an orchestration layer — you have a fragile pipeline. Build checkpointing from the start.
- **Agent-to-agent communication needs typed contracts, not chat transcripts.** Loose natural-language handoffs between agents produce non-deterministic outputs that downstream agents can't parse reliably. The Microsoft ISE case found that typed message schemas were a prerequisite for cross-team reuse.
- **Step caps and observability are not optional even at the orchestration layer.** A multi-agent graph where one node loops is worse than a single agent that loops, because the failure surface is distributed and harder to trace. Budget for per-node tracing and global step caps from day one.
