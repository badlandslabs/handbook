# S-2387 · The Orchestration Composition Stack — When Chaining LLM Calls Stops Feeling Like Enough

You have a working ReAct loop. It calls a tool, gets a result, decides what to do next. Now your product needs multiple agents that plan together, delegate to specialists, recover from failures, and stay within budget. The moment you add a second agent, your chain of LLM calls becomes an orchestration problem — and the patterns you choose determine whether you ship something that actually holds up.

## Forces

- **Chains assume known paths; agents assume unknown ones.** Linear workflows with fixed steps are underkill for open-ended tasks; full agent loops are overkill — and expensive — for deterministic ones. The spectrum between them is wide and the right choice depends on how much autonomy your task actually needs.
- **Multi-agent adds accuracy at near-double the cost.** Princeton NLP research found single agents match or outperform multi-agent on 64% of benchmarked tasks, with multi-agent adding roughly 2.1 percentage points of accuracy at approximately 2× the cost per call. Add more agents and the cost compounds: CrewAI's multi-agent pattern multiplies token usage by roughly 5× versus a single-agent equivalent.
- **Frameworks are scaffolding, not architecture.** LangGraph (39k GitHub stars), CrewAI, and AutoGen each provide different shapes of scaffolding — but Anthropic's engineering team found that the most successful production systems "use simple, composable patterns rather than complex frameworks." The framework you pick is less important than how you compose the primitives it exposes.
- **Durable execution is non-negotiable for long-running agents.** An agent that crashes mid-task and loses all progress is not production-ready. LangGraph's checkpointing, Temporal-style durable execution, and supervision hierarchies exist because production teams discovered they needed them.

## The Move

The move is choosing the right orchestration shape for your actual decision-space — not the most sophisticated one, not the simplest one that technically works. Based on field evidence from LangGraph production deployments (Klarna, Replit, Elastic), Anthropic's retrospective on hundreds of agent deployments, and framework community patterns, three composition primitives reliably appear in systems that survive production:

**1. Start at the bottom of the autonomy stack.** Anthropic recommends this hierarchy: optimized single LLM call → workflows with predefined paths → agents with tool use → multi-agent systems. Each step up trades latency, cost, and predictability for capability. Move up only when the previous level genuinely can't handle your task.

**2. Prefer graph-based state machines for anything that survives a restart.** LangGraph (used by Klarna, Replit, Elastic, LinkedIn, Uber) implements this via explicit state graphs where each node is a step and edges define transitions. The graph is durable — agents can pause, crash, and resume from checkpointed state. This matters for anything running longer than a single request. The alternative (ReAct loops with no checkpointing) works for demos; it fails in production when a network blip wipes your agent's working memory.

**3. Use the Planner/Worker/Critic split for parallelizable tasks.** The pattern (independently described by explainx.ai and used by teams at Data For Science) decomposes work into: a Planner that decomposes the task into a DAG, Workers that execute nodes in parallel, and a Critic that validates output quality. This separates concerns — the model doesn't plan and execute in the same loop — and enables level-synchronous parallelism capped by a semaphore to prevent resource exhaustion.

**4. Enforce a policy boundary between decision and execution.** The Agent Patterns site (agentpatterns.tech) calls this the "gateway" — the LLM decides *what* to do; policy logic validates *whether* it's allowed and enforces budgets. This is a fail-open vs. fail-closed question: most agent demos are fail-open (the model proposes anything). Production systems need an authorization layer that can reject actions regardless of what the model recommends.

**5. Track stop reasons explicitly.** Every agent loop needs a defined set of terminal conditions: `max_steps`, `max_tool_calls`, `max_seconds`, explicit `final` output, or an error state. Without these, agents loop indefinitely on failure. This is not optional — it is the difference between a system that fails loudly and one that burns budget silently.

**6. Combine patterns in production, not in theory.** LangGraph's own production users (Klarna, Elastic) typically run 2–3 orchestration patterns together — a supervisor at the top, a parallel fan-out for embarrassingly parallel sub-tasks, and a feedback loop for error recovery. CrewAI is often used for fast multi-agent prototyping, then replaced or hardened with LangGraph when complexity warrants.

## Gotchas

- **Most orchestration failures are cost failures, not capability failures.** The Planner/Worker/Critic split exists partly because a model doing both planning and execution in the same loop runs up token costs faster than any single optimization. Budget pressure — explicit cost ceilings per task — is a first-class concern in production, not an afterthought.
- **DAG planning upfront beats step-by-step replanning.** The explainx.ai analysis notes that a full dependency graph upfront (DAG planning) outperforms letting agents replan at each step — because replanning accumulates error and latency. If your agent iterates more than 3 times on the same subtask, your planning model and execution model should be different.
- **LangGraph's strength is also its weakness: maximum control requires maximum code.** LangGraph gives you fine-grained control over state transitions, but that means you're defining every edge and node. Teams that want faster iteration often prototype in CrewAI (lower boilerplate) and migrate to LangGraph once they need durable execution and checkpointing.
- **Checkpointing is not optional for long-running agents.** An agent that runs for 10 minutes and crashes needs to resume from where it left off, not from scratch. LangGraph's `checkpointer` and Temporal's durable execution are the two dominant approaches. Without this, you will re-run tasks that partially completed — and you will not know which ones.
- **The tool allowlist is your security boundary.** Every production agent system needs a policy gateway that validates tool calls against an explicit allowlist before execution. This is separate from what the LLM decides to do — the model can propose anything; the gateway enforces what it can actually execute. Most early agent demos skip this.
