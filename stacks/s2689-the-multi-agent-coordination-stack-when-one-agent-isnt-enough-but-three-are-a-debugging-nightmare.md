# S-2689 · The Multi-Agent Coordination Stack

When one agent can't cover the full workflow, but splitting the work across multiple agents turns a debugging problem into a debugging *system* — and the agents start arguing about who owns the state.

## Forces

- **Centralized orchestration creates a single point of failure, but decentralized coordination creates race conditions.** A single orchestrator that tells everyone what to do is easy to reason about but collapses if it goes down. Peers that negotiate work independently are more resilient but harder to debug — especially when they disagree.
- **The coordination overhead grows faster than the capability surface.** Adding a second agent doesn't double the complexity — it multiplies it by the number of communication paths, shared-state surfaces, and failure modes between agents.
- **Swarm-style decentralization sounds elegant but requires more engineering discipline than it appears.** Stigmergic coordination (agents modifying a shared environment instead of direct messaging) works for homogeneous agents but breaks down when agents have different capabilities, trust levels, or latency requirements.
- **The framework choice shapes the coordination pattern whether you like it or not.** LangGraph pushes you toward DAG-based flows; Swarms toward graph/topology-based; CrewAI toward role-based teams. Each is a reasonable choice that closes some doors.

## The Move

Map the coordination pattern to the workload shape — not the other way around.

- **Hierarchical (orchestrator + workers) for linear, high-stakes workflows.** One agent owns the plan; others execute sub-tasks. The orchestrator maintains intent and can halt the pipeline if a sub-task fails. Use when correctness matters more than throughput. Example: a research pipeline where a planner agent routes queries to a search agent, a synthesis agent, and a fact-check agent in sequence.
- **DAG (directed acyclic graph) for parallelizable, independent sub-tasks.** Multiple agents run concurrently on independent branches; results merge at a convergence point. The failure mode is a branch failing — not a cascade. Use when you have embarrassingly parallel work and need auditability of each branch. This is what most "agent pipelines" should be.
- **Swarm/topological for peer-to-peer, emergent coordination.** No single orchestrator. Agents publish to a shared state (blackboard pattern) or modify a shared environment (stigmergy). Each agent reads the environment and acts independently. Best for homogeneous tasks where many agents can perform the same role — document processing, parallel web scraping, bulk classification.
- **Hierarchical+swarm hybrid for production at scale.** A top-level orchestrator manages agent teams; each team uses swarm-style peer coordination internally. Used by enterprise deployments with thousands of daily agent invocations. The Swarms framework (6.8k stars, Apache 2.0) explicitly models this as "agent teams" with topology-aware routing.
- **State management: pass references, not full context.** In hierarchical/DAG flows, don't pass entire conversation history between agents — pass IDs pointing to a shared state store. The Zylos Research analysis on swarm coordination identifies shared-environment state as a bottleneck and failure point; agents waiting for state to settle is a primary deadlock cause. Use optimistic updates with eventual consistency, not distributed locks.
- **Timeout escalation with escalation chains.** If an agent doesn't respond within N seconds, escalate to a supervisor agent rather than retrying. This prevents hung agents from blocking the entire pipeline. CrewAI and LangGraph both support supervisor-style handoffs as first-class primitives.
- **Treat agent handoffs as API contracts.** Define what each agent receives as input and what it must produce as output — a schema, not a prompt. This makes handoffs testable, observable, and refactorable. Without contracts, you're debugging free-form text passed between two non-deterministic systems.

## Evidence

- **arXiv paper (2512.08769, Dec 2025):** Survey of production agentic deployments across financial services, healthcare, and developer tooling found 9 best practices for production-grade workflows. Key finding: heterogeneous multi-model pipelines (OpenAI + Gemini + Claude across different agents) outperform single-model monolithic agents on complex tasks — because each agent uses the model best suited to its sub-task. Agents coordinating via API-level contracts outperform those using shared-prompt-passing by 40% on task completion rate. — [arXiv:2512.08769](https://arxiv.org/html/2512.08769v1)
- **Zylos Research (May 2026):** Deep analysis of swarm intelligence applied to AI agents. Found that stigmergic coordination (shared environment) works for up to ~20 homogeneous agents but degrades sharply past that threshold due to state contention. Hierarchical control scales linearly with team size but creates bottlenecks. The recommended production pattern is "bounded swarms" — small peer groups (5-8 agents) coordinated by a lightweight supervisor, avoiding both the bottleneck and the state contention problem. — [Zylos Research](https://zylos.ai/en/research/2026-05-23-swarm-intelligence-multi-agent-coordination-patterns)
- **MMC Ventures primary research (Nov 2025):** Interviewed 30+ European agentic AI startup founders and 40+ enterprise practitioners. Found that >90% of startups achieve 70%+ accuracy in agentic workflows, but enterprise deployment challenges are primarily organizational (workflow integration, employee adoption), not technical. The single biggest technical lesson: "Agents that own end-to-end workflows need explicit handoff boundaries — treating handoffs as implicit is the leading cause of production failures." — [MMC Ventures State of Agentic AI](https://mmc.vc/research/state-of-agentic-ai-founders-edition/)
- **Swarms framework (GitHub):** 6.8k stars, 434 dependents, Apache 2.0. Provides 10+ swarm topologies as first-class primitives including sequential, concurrent, hierarchical, graph-based, and agent-team models. Supports MCP protocol and integrates with LangChain, AutoGen, and CrewAI. Key architectural decision: exposes topology as a configuration parameter rather than a code change — making it possible to A/B test coordination patterns against the same agent logic. — [Swarms Framework](https://www.swarms.ai/framework)
- **AppScale blog (2026):** Analysis of tool-calling schema design for multi-agent systems. Identifies that in production, the tool registry becomes a coordination surface — agents effectively negotiate by publishing capabilities, not by direct messaging. Schema versioning is critical: breaking changes to a shared tool schema break all agents that depend on it simultaneously. — [AppScale Blog](https://appscale.blog/en/blog/ai-service-pattern-tool-calling-schema-design-llm-agents-2026)

## Gotchas

- **Don't start with swarm unless you need emergent behavior.** Swarm coordination requires homogeneous agents, a shared state mechanism, and tolerance for non-deterministic ordering. Most workflows are better served by a clear DAG with explicit dependencies.
- **Shared mutable state between agents is a distributed systems problem you're pretending isn't.** Two agents writing to the same variable at the same time behave like two threads sharing a lock — except neither thread is deterministic. Use a state store (Redis, Postgres, S3) with defined read/write ownership per agent, not in-memory shared dictionaries.
- **Context passing between agents is a memory problem you inherit.** An agent that receives 80K tokens of conversation history from its parent will spend a disproportionate amount of its context window re-reading what it already knew. Summarize at handoff boundaries, not just at the end of the session.
- **Multi-agent systems multiply observability requirements.** Tracing a single agent is hard enough. Tracing 5 agents making 20 tool calls across 3 models, with 4 handoffs and shared state, requires OpenTelemetry span correlation from day one. Retrofitting it is painful.
- **AgentKit killed Swarm but the lessons from Swarm's failure are canonical.** OpenAI deprecated Swarm (Oct 2024) but its pattern — lightweight handoffs with shared context — remains the right mental model. AgentKit is the hardened production version. If you're starting fresh, use AgentKit or LangGraph's state graph; if you're maintaining Swarm-style code, migrate before the model API changes break your assumptions.
