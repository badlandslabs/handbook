# S-2519 · The Agent Memory Stack — When Your Agent Forgets Everything Between Sessions

Your agent aced the session. It closed the ticket, filed the report, drafted the email. You opened a new session and it asked you to re-explain the project structure. Again. This is the Goldfish Problem — agents that are stateless by default, built on the assumption that one context window equals one session. It doesn't. The move is treating memory as a first-class subsystem you engineer, not a prompt you stuff things into.

## Forces

- **Context windows and agent memory are different systems.** A context window is a per-call input buffer that resets every request. Agent memory is what you build so the model can recall what happened yesterday, last week, or three sessions ago. Growing the window doesn't give you cross-session continuity — it just gives you a larger room that still empties when you leave. — [Redis, June 2026](https://redis.io/blog/why-bigger-context-window-wont-fix-agent-memory)
- **87% of agent failures stem from missing context.** The agent doesn't fail because it lacks capability — it fails because it lacks history. It re-investigates the same bugs, re-discovers the same constraints, re-explains the same project conventions to itself. — [Engram, 2026](https://engram-ai.dev/)
- **Three fundamentally different architectural patterns now dominate production.** Vector-first extraction, graph-native temporal knowledge, and OS-inspired tiered context. Picking the wrong one for your use case means expensive rewrites. — [AI Workflow Lab, June 2026](https://aiworkflowlab.dev/article/agent-memory-mem0-vs-letta-vs-zep-2026)
- **Memory staleness is the silent killer.** 97.8% of entries in one audited memory store were junk after 32 days without active maintenance or verification. Unverified memory compounds error, not capability. — [Contextos AI / DevoxxGenie, 2026](https://genie.devoxx.com/blog/engram-persistent-memory)

## The move

Build memory as a tiered subsystem with distinct write, store, retrieve, and expire paths — not as a dump of everything into a vector DB.

- **Separate the layers: working, episodic, semantic, procedural.** Mem0 (vector-first extraction) works for personalization and chat compression. Zep/Graphiti (temporal knowledge graph) works for CRMs and support agents where *when* a fact changed matters. Letta (tiered memory blocks) works for long-running agents that need editable, archival-aware context. The flat-file + hybrid search approach (BM25 0.6 / vector 0.4 weighting) works when you want zero external dependencies and agent-readable files. — [AI Workflow Lab](https://aiworkflowlab.dev/article/agent-memory-mem0-vs-letta-vs-zep-2026), [Brueggeman, March 2026](https://agent-memory.bruegs.com/)
- **Write async by default.** Blocking memory writes on the response pipeline adds latency users feel. Make async the default; sync only when you need the write confirmed before responding. — [Mem0, 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- **Rerank retrieval candidates.** Vector similarity returns the right candidates but often in the wrong order. Cross-encoder reranking improves precision by re-scoring the top-K against the query with full cross-attention. — [Mem0](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- **Design for memory expiry and verification, not just storage.** Raw storage without lifecycle management turns into noise. The 97.8% junk figure is a warning: dedup and verify pipelines are the difference between an agent that gets smarter and one that gets weirder. — [Contextos AI](https://genie.devoxx.com/blog/engram-persistent-memory)
- **Measure on LoCoMo and LongMemEval.** LoCoMo (1,540 questions, single/multi-hop, temporal recall) and LongMemEval (500 questions, knowledge updates, multi-session recall) are the emerging standard benchmarks. Hardest open problems: cross-session identity, temporal abstraction at scale, and memory staleness. — [Mem0](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- **For coding agents: use MCP-backed shared memory across sessions.** Engram (sub-millisecond recall, MCP protocol) gives coding agents a shared durable layer that survives IDE restarts and session resets — storing design decisions, root causes of bugs already investigated, and failed approaches that shouldn't be repeated. — [DevoxxGenie / Engram, June 2026](https://genie.devoxx.com/blog/engram-persistent-memory)
- **Knowledge graphs as world models.** Flat document retrieval hits a structural ceiling — it finds relevant text but can't navigate relationships or reason across hops. Temporal knowledge graphs (Graphiti, Cognee, Neo4j) encode entities and relationships as queryable first-class citizens, giving agents a traversable representation of what they know that evolves over time. — [Zylos Research, May 2026](https://zylos.ai/zh/research/2026-05-09-knowledge-graph-world-models-ai-agents)

## Evidence

- **GitHub Handbook:** The AI Agent Engineering Handbook (vasilyevdm, March 2026) analyzed 30+ agent frameworks' source code and documented that "context quality degrades early and rapidly" — the compaction, system-prompt assembly, and memory-tier design are what separate production agents from demos. — [github.com/vasilyevdm/ai-agent-handbook](https://github.com/vasilyevdm/ai-agent-handbook)
- **Benchmarking:** Mem0 reports 92.5 on LoCoMo and 94.4 on LongMemEval at ~6,900 tokens per query, with +29.6 points on temporal reasoning and +23.1 on multi-hop recall. The flat-file + hybrid search approach (Brueggeman) achieved 74% on LoCoMo file-only, +113% recall score improvement with zero external API dependencies. — [mem0.ai](https://mem0.ai/blog/state-of-ai-agent-memory-2026), [agent-memory.bruegs.com](https://agent-memory.bruegs.com/)
- **Production deployment:** Mem0 served 186 million API calls in Q3 2025 as the exclusive memory provider for AWS's Agent SDK. Zep's Graphiti powers production agents with temporal knowledge graph architectures at scale. Engram is integrated into the DevoxxGenie IDE plugin suite used by Java developers. — [TechCrunch via Mem0](https://mem0.ai/compare/mem0-vs-letta), [github.com/Memory-Agents/graphiti](https://github.com/Memory-Agents/graphiti/), [genie.devoxx.com](https://genie.devoxx.com/blog/engram-persistent-memory)

## Gotchas

- **Async writes that silently fail corrupt memory silently.** If a memory write fails and you don't surface the error, you won't know what the agent forgot. Log failures, surface them in development, and consider a write-verification path in production.
- **The flat-file approach is zero-dependency but doesn't scale past one agent.** Once you have multiple agents writing to shared files, you need locking, conflict resolution, or a real database. The flat-file wins for solo coding agents; it breaks for team or multi-agent setups.
- **Graph extraction write latency is high.** Temporal knowledge graphs (Zep/Graphiti) have ~300–800ms write latency from graph extraction vs ~80–200ms for Mem0's async vector writes. If your agent needs sub-100ms response times, graph-native memory adds perceptible overhead.
- **Memory poisoning is a real attack surface.** ASI06 and OWASP named memory poisoning a top-10 agentic risk in 2026. Without provenance tracking and deduplication, adversaries can inject facts that survive verification and compound across sessions. — [Contextos AI](https://genie.devoxx.com/blog/engram-persistent-memory)
