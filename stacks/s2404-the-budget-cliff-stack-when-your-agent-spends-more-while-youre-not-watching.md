# S-2404 · The Budget Cliff Stack — When Your Agent Spends More While You're Not Watching

You deploy an agent. It works. You ship it. Three weeks later your CFO asks about a $12,000 API bill from a product that was supposed to cost $200/month. The agent wasn't malicious — it was just doing its job, generating more tokens per task than anyone estimated, retrying more than anyone tested, and accumulating context that made every subsequent step more expensive. You found out from the invoice, not from an alert. The budget cliff is the moment between "reasonable spend" and "runaway costs" that your observability never caught, because you weren't measuring what actually costs money.

## Forces

- **Agentic systems are expensive by design.** A chat uses a few thousand tokens. An agent uses tens or hundreds of thousands across planning, tool calls, retries, and verification loops. ProjectDiscovery's security agent consumed 60 million tokens for a single complex task before optimization — at full price, that was hundreds of dollars per task
- **Token costs compound quadratically in multi-turn agents.** Per-turn costs look small. Across 20-40 steps per task, with each step reading the accumulated context, the bill grows faster than linearly. The HN discussion "Expensively Quadratic" (131 points) named this explicitly: by 50,000 tokens, cache read costs begin dominating — and cache reads are not free
- **Spend is invisible until it's a crisis.** Traditional rate limiting tracks HTTP requests. LLM APIs bill in tokens. A client sending 50 req/min can trigger thousands in spend if those requests are large. Most teams have request observability before they have token-cost observability
- **The controls that make agents powerful are orthogonal to financial controls.** LangChain, AutoGen, CrewAI — the frameworks that made agentic AI accessible did not ship with budget enforcement. The architecture that enables capability does not include a mechanism to stop it from running indefinitely — the $47,000 eleven-day incident was a multi-agent LangChain system
- **Optimizing for capability and optimizing for cost pull in opposite directions.** More retries improve success rates. More context improves quality. More exploration improves coverage. All of them cost more. Teams that don't separate these concerns discover the tradeoff only after the bill arrives

## The move

The budget cliff is structural. It requires a layered governance stack built before deployment, not a retroactive fix after an incident. The four-layer model from Matheus Palma's cost governance framework (admission → routing → execution → reconciliation) gives each layer a specific, non-overlapping role.

### Layer 1 — Prompt Caching (Biggest ROI, Structural Fix)

Structure every agent prompt in three zones, from top to bottom: stable prefix (system prompt, tool definitions, reference docs), contextual prefix (session history, retrieved context), dynamic tail (current user query, task-specific inputs). Mark the stable and contextual zones with your provider's cache control markers — `cache_control` for Anthropic, `cache` for OpenAI. The critical insight: **anything dynamic in the middle of a cached prefix invalidates everything after it**. ProjectDiscovery restructured their agent prompts this way and moved their cache hit rate from 7% to 84%, cutting total costs by 59% (9.8 billion cached tokens served in a year). OpenHelm achieved 60% savings on their research agent (£4,200 → £1,680/month). Anthropic charges 90% less for cached tokens, OpenAI 50% less, Gemini 75% less.

### Layer 2 — Model Routing (60-85% Savings on 60% of Tasks)

Route queries to the cheapest model that can handle them reliably. A classifier or simple heuristic reads each incoming task and dispatches to Haiku-class, Sonnet-class, or Opus-class models based on complexity. Berkeley LMSys's RouteLLM (ICLR 2025, 5,315 GitHub stars) demonstrates 85% cost reduction on MT Bench at 95% of GPT-4 quality, 45% reduction on MMLU, and 35% on GSM8K. IBM reports $0.05 savings per query versus always routing to GPT-4. Global telecom enterprises report 42% cost reduction with smaller models handling 60% of tasks. RouteLLM can use embedding-based similarity matching, a fine-tuned classifier, or LLM-as-judge as the routing mechanism. FrugalGPT (Chen et al., 2023) uses a cascade approach: start with the cheapest model, escalate only if confidence thresholds aren't met.

### Layer 3 — Budget Enforcement at Runtime

Enforce token and spend limits at the agent runtime level, not the API level. Configure three granularities: per-task (hard cap on tokens per individual LLM call), per-session (hard cap on total tokens across a single user session), and per-project/month (aggregate budget with percentage alerts at 50%, 80%, 100%). The key insight from AgenticSkillset.org's token budget guide: **RAG recursion is the most common cause of uncontrolled budget consumption in production** — a poorly phrased retrieval query can expand into a multi-turn loop that re-reads the entire knowledge base on every step. Budget enforcement must be placed before LLM invocation, not as an after-the-fact log check.

### Layer 4 — Cost Observability (Prerequisite for Everything Else)

Measure what actually costs money. Track: tokens in and out per task, per user, per agent type; cache hit rate; cost per successful task (including retry cost); spend vs. budget at per-session and aggregate levels. ProjectDiscovery monitors cache hit rate as a leading indicator — drops signal prompt structure problems before they appear in the bill. The $47,000 eleven-day runaway was detected by a monthly billing statement, not by an alert. The fix was adding per-agent spend limits, step-count limits, and anomaly detection on token consumption. Without observability, there is no governance.

## Gotchas

- **Caching only the beginning is a guess, not a strategy.** Teams add cache markers to the system prompt and assume they're done. If context grows past the cache window, or if dynamic content appears early in the prefix, the cache invalidates silently and costs return to full rate. Verify your cache hit rate in production, not just in testing
- **Output tokens are not cached.** Anthropic's 90% discount applies to input cache reads. Completion tokens are always full price. Agents with verbose reasoning chains (Chain of Thought, tool-use descriptions, multi-step verification) pay full output price on every step — caching input prefixes doesn't help here
- **Per-call budgets are not per-task budgets.** Setting `max_tokens=4096` on each API call still allows an agent to make 50 calls. Per-session and per-project budgets are what prevent the 11-day runaway scenario
- **The cheap model is not always cheaper at the task level.** If a Haiku query fails and requires 3 Sonnet retries to recover, you've paid more than running Sonnet once. RouteLLM's 95% quality threshold is the load-bearing assumption — measure cost per *successful* task, not cost per call
- **Budget enforcement without alerting is a safety net, not observability.** A hard cap that blocks a session is correct behavior. But you also want to know when you're approaching the cap — alerting at 50% and 80% lets you investigate before the 100% cutoff, which matters when the budget is too conservative for your actual workload
