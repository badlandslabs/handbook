# S-2302 · The Goldfish Reboot Stack — When Your Agent Forgets Everything Between Sessions

Your agent can reason across a 64K context window in a single session. But two days later, it greets the same user like a stranger. Every session starts from zero. Every conversation is a fresh mind. The demo worked. The production system doesn't compound value — it resets. This is the Goldfish Reboot: the gap between what agents can do within a session and what they can carry across sessions.

## Forces

- **Standard RAG retrieval is wrong for agent memory.** RAG was designed for large, diverse document corpora. Agent memory is a bounded, coherent dialogue stream — highly correlated spans, near-duplicate content, temporally entangled evidence chains. Fixed top-k similarity retrieval collapses into a single dense region, returning redundant context while losing prerequisite facts. — [arXiv:2602.02007](https://arxiv.org/html/2602.02007v1)
- **Retrieval is close to solved; synthesis isn't.** AutoMem benchmarks show 97% retrieval accuracy but only 87% answer accuracy. The gap is where production systems actually fail. — [AutoMem Blog, June 2026](https://automem.ai/blog/agent-memory-in-2026-an-honest-comparison-of-mem0-zep-letta-and-the-rest)
- **No single storage paradigm dominates.** Production-grade agents use hybrid vector-graph architectures with LLM-managed interfaces that decide what to store, when to retrieve, and when to forget. — [Zylos Research, April 2026](https://zylos.ai/research/2026-04-05-ai-agent-memory-architectures-persistent-knowledge/)
- **Benchmark numbers are mostly self-reported** with different models, judges, and dataset slices. Pick on architecture and failure mode, not the headline percentage. — [AutoMem Blog, June 2026](https://automem.ai/blog/agent-memory-in-2026-an-honest-comparison-of-mem0-zep-letta-and-the-rest)

## The Move

Build a four-tier memory architecture that treats episodic, semantic, and procedural memory as distinct engineering problems with separate storage backends and retrieval rules.

- **Working memory (in-context):** Current task state stored in-process (LangGraph state, conversation buffer). Always in context. Evicted at session end. Size-managed by the agent harness — not a database.
- **Episodic memory (summarized past):** Conversation summaries and event records stored in a vector database with temporal metadata. Retrieved by similarity to the current query. Compressed via progressive summarization (raw → key points → one-liner → tags) so older sessions cost less to retrieve. — [Synthara Technologies, May 2026](https://www.syntharatechnologies.com/blog/agent-memory-architectures)
- **Semantic memory (extracted facts):** Declarative facts about users, entities, and world state stored in a relational schema or knowledge graph — not raw text. Mem0 and Zep both use LLM extraction to convert dialogue into structured facts. Zep adds a validity window to every fact, enabling "what was true on date X" queries. — [arXiv:2501.13956](https://arxiv.org/html/2501.13956v1)
- **Procedural memory (learned routines):** Behavioral heuristics and workflow policies stored in versioned documents (git or DB). Retrieved by intent + role. The agent's "personality" — how it approaches tasks, what defaults it uses, which tools it prefers — lives here. — [Synthara Technologies](https://www.syntharatechnologies.com/blog/agent-memory-architectures)
- **Hybrid retrieval at query time.** Don't rely on a single retrieval method. Combine vector similarity (for topical recall), entity/graph traversal (for relationship queries), and keyword/BM25 (for exact-match fallback). The xMemory paper shows that decoupling memories into semantic components before retrieval outperforms flat RAG on agent-specific benchmarks. — [arXiv:2602.02007](https://arxiv.org/html/2602.02007v1)
- **Tiered summarization schedule.** Recent events (7 days) kept raw. Older events summarized at 1-week granularity. Very old events distilled into semantic tags. This keeps token costs bounded while preserving decision-relevant detail. — [Prompt Engineering Zero to Hero](https://promptz2h.com/chapter_13_agentic_systems_engineering/series_03_agent_memory_and_state_systems/memory_summarization_techniques)
- **Write-time LLM extraction (or its equivalent).** Systems like Mem0 and Zep pay the LLM cost at write time — converting raw dialogue into structured facts — so retrieval is fast and deterministic. The tradeoff: every write costs an LLM call. The benefit: retrieval doesn't need a full LLM to make sense of a haystack.

## Evidence

- **Bilt (1M+ user agents):** Bilt, a housing and neighborhood commerce network, used Letta's memory-augmented agents to build personalized recommendations for over one million users. Processed user data into shared memory blocks, then used smaller/faster models for inference — enabled by the structured memory layer reducing context requirements. — [CaseStudies.com / Letta](https://www.casestudies.com/company/letta/case-study/how-bilt-built-a-million-agent-recommendation-system-with-letta)
- **Kognitos (enterprise analytics):** Kognitos used Letta to build a business analytics agent for a logistics client with 4,000+ poorly labeled tables. The agent needed to maintain context across conversations with different executive personas (CEO, CFO, CIO), remember previous query chains, and build on prior insights — all requiring persistent memory at the semantic and episodic tiers. — [Letta Case Study](https://www.letta.com/case-studies/kognitos)
- **11x.ai (AI-native sales):** 11x.ai (featured on Letta's case studies page) uses memory-augmented agents for AI-powered sales. The agent learns from each outreach interaction, remembers which approaches failed, and adapts its strategy over time — requiring procedural memory for behavioral policies and episodic memory for past interaction outcomes.

## Gotchas

- **Don't use standard RAG retrieval for agent memory.** Top-k cosine similarity on conversation chunks produces redundant, temporally collapsed results. The fix: structure-aware retrieval that respects dialogue boundaries, temporal ordering, and co-reference chains. — [arXiv:2602.02007](https://arxiv.org/html/2602.02007v1)
- **Don't skip the forget signal.** Without explicit forgetting (TTL policies, decay functions, validity windows), memory grows unbounded and retrieval signal-to-noise degrades. Zep's bi-temporal model (valid_from / valid_to on every fact) handles this structurally. MemoryBank's Ebbinghaus-curve decay is another pattern. — [Memory Atlas / Zep Deep Dive](https://www.memoryatlas.dev/articles/zep-deep-dive)
- **Don't pay LLM cost at both read and write.** If you're doing LLM-based retrieval (re-ranking, query expansion) AND LLM-based writing (fact extraction), you're paying twice. Pick one: structured write (Mem0, Zep) for fast retrieval, or raw storage with heavy retrieval-time synthesis.
- **Benchmark comparison is unreliable.** Mem0 and Letta are measured on different benchmarks (LoCoMo vs DMR, different models). agentmemory benchmarks on LongMemEval-S show 95.2% with BM25+vector, but Letta/Mem0 aren't measured on the same test. Don't compare headline numbers across systems. — [agentmemory/COMPARISON.md](https://github.com/Acumenllc/agentmemory/blob/main/benchmark/COMPARISON.md)
