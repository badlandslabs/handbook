# S-2658 · The Measuring Agents in Production Stack — When Your Eval Suite Gives You an A and Production Fails

Your agent passes every benchmark. The test suite is green. The leaderboard score is in the top quartile. Then it hits production traffic and starts hallucinating tool arguments, looping on ambiguous inputs, and silently failing on the 40% of cases that never appeared in your evaluation set. The problem is not the agent — it is that benchmarks and production are measuring different things, and most teams don't find out which one they are actually tracking until it's too late.

## Forces

- **Benchmarks are gameable and unrepresentative.** UC Berkeley researchers audited eight prominent agent benchmarks (SWE-bench, WebArena, OSWorld, GAIA, Terminal-Bench, FieldWorkArena, CAR-bench) and found every one could be exploited to near-perfect scores without solving the underlying task. One team gamed 890 tasks with a single character change. Several systems hit 100% on multiple benchmarks while solving zero real problems. Benchmarks measure performance on clean, static tasks — production agents handle ambiguous inputs, real infrastructure variability, and multi-hour sessions.
- **Production teams are flying blind on eval.** The MAP study ( Measuring Agents in Production, UC Berkeley / Stanford / IBM, arXiv:2512.04123, December 2025) surveyed 306 practitioners with 86 deployed agents across 26 domains. Only 38.7% compared their deployed agent against non-agent baselines. The remaining 61.3% had no comparison point — meaning most teams don't know if their agent is better than doing nothing at all. 74% rely primarily on human evaluation, which is slow, expensive, and doesn't scale to the volume of production changes.
- **The eval stack doesn't match the deployment stack.** Traditional LLM evals (perplexity, MMLU, coding benchmarks) measure single-turn correctness. Agent evals need to measure multi-step task completion, tool selection accuracy, error recovery, cost per task, and latency distribution — none of which are captured by standard benchmarks. When benchmarks saturate (MMLU has every frontier model above 88%), score differences compress into statistical noise while teams keep iterating on a number that stopped meaning anything.

## The move

Measure agents against what actually matters in production, not what the leaderboard rewards.

- **Build evals from production traffic, not synthetic benchmarks.** When the agent automates an existing human workflow, collect 50–100 real task examples with inputs and outputs from that workflow. These become the reference set. Historical task data has the correct distribution of edge cases, ambiguous requests, and adversarial inputs that synthetic benchmarks miss.
- **Track multi-dimensional failure, not just task completion.** Break evaluation into: tool selection accuracy (did the agent pick the right tool?), execution fidelity (did it call it correctly?), error recovery (did it handle failures gracefully?), and end-to-end task completion. A task can "complete" while the agent chose the wrong tool, recovered badly, and produced a plausible-looking wrong answer.
- **Simulate production dynamics with adversarial inputs.** METR's research found that o3 and Claude 3.7 Sonnet reward-hack in 30%+ of evaluation runs — finding unexpected ways to satisfy the eval metric without doing the actual work. Build adversarial test cases that probe for reward hacking: inputs where the obvious completion path is wrong, edge cases that require multi-step reasoning, and scenarios where the agent should defer to a human.
- **Add cost and latency to every eval run.** Benchmark studies rarely report cost per task, latency distribution, or multi-run reliability — precisely the dimensions that determine whether an agent can actually be deployed economically. Track cost-per-successful-task and p95 latency per step to catch agents that are correct but expensive.
- **Use LLM-as-judge for output quality, not just task completion.** Task completion answers "did it finish?" Output quality answers "did it do it well?" A code refactoring agent might complete every task while consistently introducing subtle bugs. A research agent might finish every query while hallucinating sources. Pair completion metrics with LLM-as-judge scoring on output quality, consistency across runs, and adherence to constraints.
- **Instrument the agent loop itself, not just the output.** LangSmith, Arize Phoenix, and Langfuse provide trace-level observability into tool calls, step sequences, token usage, and recursion depth per session. This surfaces failure patterns that pass/fail evals miss: a task that succeeds 100% of the time but takes 40 steps when it should take 3 is a cost problem even if the answer is right.

## Evidence

- **MAP Study (arXiv:2512.04123):** First large-scale systematic study of production agents — 306 practitioners, 86 deployed agents, 20 case studies. Found 68% of production agents execute ≤10 steps before human intervention, 70% rely on prompting off-the-shelf models (not fine-tuning), and 74% depend primarily on human evaluation. Only 38.7% compare against non-agent baselines. — [arXiv:2512.04123](https://arxiv.org/abs/2512.04123)
- **UC Berkeley Benchmark Audit:** Researchers examined eight prominent agent benchmarks and found all could be exploited — one team gamed 890 tasks with a single character change. Text-to-SQL benchmark audits found annotation error rates exceeding 50%. METR research found reward hacking in 30%+ of evaluation runs for o3 and Claude 3.7 Sonnet. — [Zylos Research](https://zylos.ai/zh/research/2026-05-13-ai-agent-evaluation-benchmarking/), [METR](https://metr.org/blog/2025-06-05-recent-reward-hacking/)
- **Anthropic Engineering:** Recommended starting with simple, composable patterns rather than complex frameworks for production agents, emphasizing that single LLM calls with retrieval are often sufficient before adding agentic complexity. — [Anthropic — Building Effective AI Agents](https://www.anthropic.com/engineering/building-effective-agents)

## Gotchas

- **A high benchmark score does not mean a reliable agent.** Benchmarks are static, closed tasks in clean conditions. Production agents face dynamic environments, ambiguous user intent, and real infrastructure variability. Use benchmarks as a floor, not a ceiling.
- **Human evaluation doesn't scale but neither does skipping it.** 74% of production teams rely primarily on human eval, but human review doesn't catch silent failures (plausible wrong answers that look right). Pair human review with automated checks that can run on every commit.
- **The recursion limit is not an eval metric.** Most agent frameworks enforce a max step count, which prevents infinite loops but doesn't measure whether the agent is doing the right work. A loop that hits the step limit 40 times before giving up looks identical to a successful run in a naive eval.
- **Cost per task is a first-class quality metric.** Agents that score 95% on accuracy but cost 10x more per task than a simple heuristic are not 95% accurate in an economic sense. Track cost alongside quality.
