# S-1747 · The Hierarchical Orchestration Stack — When Your Agent Fleet Lacks a Coordinator

You have multiple agents — a researcher, a coder, a reviewer, a writer. They each have their own tools. But when you wire them together, work gets duplicated, agents argue with each other, outputs pile up in the wrong order, and debugging is a nightmare. You've tried making them all peers and it falls apart. You need a coordinator that owns the plan.

## Forces

- **One agent can't do everything well.** A "god agent" that handles research, writing, and review hits context limits, confuses reasoning modes, and can't parallelize independent tasks. But N independent peer agents with no coordinator fragment work and produce inconsistent outputs.
- **Peer-to-peer doesn't scale.** Fully distributed agent meshes (swarm pattern) work in demos. In production they create race conditions, circular dependencies, and unpredictable convergence. Every team that goes peer-to-peer hits the same wall around 3-4 agents.
- **Over-architecting is the most common failure.** LangChain's 2025 production survey found simple chains handle 80% of production use cases, yet teams consistently start with complex multi-agent systems before proving they need them. The cognitive overhead of coordinating N agents is multiplied by the complexity of the coordination layer.
- **Framework choice is irreversible at scale.** Moving from CrewAI to LangGraph or vice versa means rewriting the orchestration layer. Pick the philosophy that matches your production needs — not the one with the best marketing.

## The Move

**Use a supervisor agent to own task decomposition and result integration.** The supervisor is the only agent that sees the full context; specialists only see their slice. This is the "hub-and-spoke" or "orchestrator-worker" pattern, and it dominates production because it's the simplest architecture that actually coordinates work.

Specific moves:

- **Define clear contracts per specialist.** Each specialist agent gets a typed input schema and a typed output schema. The supervisor's job includes validating specialist outputs against those schemas before feeding them downstream. Ambiguous contracts between agents are the #1 failure mode.
- **Make the supervisor own failure routing.** When a specialist fails or returns ambiguous output, the supervisor — not the specialist — decides: retry, skip, escalate to human, or terminate. Specialists should not make routing decisions; that requires the full-context view the supervisor holds.
- **Start with a sequential pipeline, not a graph.** The simplest supervisor pattern is a linear sequence: supervisor decomposes → specialist A executes → specialist B executes → supervisor integrates → returns result. Only add branching (parallel specialists, conditional paths) when latency or independence demands it. The graph comes after the pipeline proves itself.
- **Use checkpointing for long-horizon tasks.** LangGraph's checkpointing lets you suspend and resume agent state mid-execution. For tasks that span minutes or hours, this prevents catastrophic restarts. Even a simple Redis-backed state store dramatically improves recovery behavior.
- **Choose the framework that matches your production discipline bar.** LangGraph (graph-based state machines) for compliance-heavy, observability-demanding, audit-required production. CrewAI (role-based crews) for rapid prototyping and non-engineer teams. Microsoft's Agent Framework (successor to AutoGen, April 2026) for Azure-centric enterprise. These are three genuinely different philosophies, not three flavors of the same thing.

## Gotchas

- **Don't start with a swarm.** Fully distributed, peer-to-peer agent meshes look elegant on whiteboard architecture diagrams. In production they produce circular dependencies, no single source of truth for task state, and debugging that requires reading logs from N agents simultaneously. The swarm pattern is for narrow, well-bounded domains — not general-purpose orchestration.
- **Don't give specialists the full context.** The temptation is to pass the entire conversation history to every specialist so they can "see the big picture." This produces inconsistent outputs (specialists interpret the context differently), inflates token costs, and makes debugging harder. Specialists should receive typed task inputs and return typed outputs. The supervisor holds the full picture.
- **Don't choose a framework based on v0 demos.** CrewAI's role-based agent abstraction makes it fast to prototype. But if your production bar requires checkpointing, human-in-the-loop approvals, compliance audit trails, and cost predictability, you'll spend months fighting CrewAI's abstractions. LangGraph's steeper learning curve pays off in production control.
